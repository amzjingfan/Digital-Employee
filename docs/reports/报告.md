## 2. 项目是做什么的

Joukir 是基于 StaffDeck 扩展的跨境电商企业 AI 工作台。产品定位是**把 SOP 从文档变成可运行、可审批、可复盘的数字员工部门**：真人给数字员工派任务，数字员工在授权范围内查询知识和业务数据、调用受限工具、形成判断或草稿；高风险操作转人工审批，系统记录任务、证据、Trace 和结果。目标业务涵盖售后、Listing、物流、广告、设计、采购、运营以及 TikTok 事业部。

一条设计中的业务闭环是：

```text
真人/事件/定时触发 → 创建任务 → 校验租户、岗位和资源权限
→ 固定数字员工/SOP/知识/工具版本快照 → 读取授权数据与知识
→ 只读工具/模型分析 → 记录 Trace 与 Evidence
→ 人工复核或高风险审批 → 受控执行/结案 → 反馈、复盘与后续任务
```

当前本地环境主要支持读取、分析、草稿、Mock/Sandbox 演练和人工复核。退款、发布、调价、改广告预算、佣金、发样等外部写动作不能因为界面或代码中有入口就视为可用或获准上线。

项目根目录的 [README.zh.md](../../README.zh.md)、[产品需求文档](../prd/crossborder-digital-workforce-prd-2026.md) 和 [项目长期记忆](../PROJECT_MEMORY.md) 分别说明产品、规划与实际开发约束。许可证为 AGPL-3.0。

## 7. SOP 怎样工作，目前做到哪里

### 7.1 平台通用 SOP

SOP 不是单纯的提示词。设计要求它固定步骤、条件、分支、重试、人工门禁和终止条件，并与员工岗位、知识版本、工具权限绑定。作者先创建/生成草稿，再校验引用资源和权限，经过人工审核后发布版本；运行时只取当前可见且已发布的 SOP，任务领取时固定员工、SOP、知识和工具快照，记录摘要。每一步的输入、引用、工具结果、审批与输出应进入 Trace；版本变化不能让正在执行的任务偷偷改用新内容。需要外部高风险动作时先形成审批请求，未获准不能执行；人工接管后也应保留在同一任务链中。

当前数据库中有 45 个已发布 Skill，但 `api_sop_drafts` 为空；这表示没有该 Open API 草稿表里的存量草稿，**不表示系统没有 SOP**。本轮验证范围是部分已发布只读能力、五条 TikTok 确定性 Mock 回放与后端相关测试，没有把 SOP 编辑→发布→真实任务→回滚全部点通。

### 7.3 TikTok 十二条业务 SOP 的真实状态

产品规划列有 12 条跨部门 SOP。**本轮真正通过确定性 Mock 回放的是五条**：`TT-SOP-002` 短视频内容工厂、`003` 小店巡检、`004` 广告只读巡检、`007` 商达匹配、`009` 直播开播前检查。回放校验任务创建、知识命中、只读 Mock 工具、Trace、Evidence 和后续待办，`5/5` 通过、`external_writes=false`；每条又覆盖缺知识、授权冲突、超时、重复、Scope 撤销和人工接管，异常矩阵 `30/30` 通过。

其余七条——`001` 商机到入驻、`005` 广告变更、`006` TAP 授权入驻、`008` 样品与内容交付、`010` 直播实时异常、`011` 直播复盘、`012` 事业部日报周报——主要是规划/模板或依赖真实授权和外部执行的后续切片，**不能认定已按完整真实业务 SOP 上线**。即使五条 Mock 已通过，TikTok 官方授权和外部写入仍未放行；演示审批编号不能代替业务负责人生产签字。
