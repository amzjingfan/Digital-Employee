# Issue tracker policy

Repository agents do not create, edit, close, label, or otherwise manage issues. Record implementation work in the pull request, `docs/DEVELOPMENT_LOG.md`, and `docs/SESSION_HANDOFF.md` instead.

Human maintainers may use the eventual GitHub repository's issue tracker. An agent may read an issue supplied by a maintainer as task context, but must not change external issue state unless the maintainer explicitly authorizes that action.
