# 社媒运营 SaaS 并行分支开发记录

## 2026-09-08 · P0 达人证据与受众冻结闭环（开始）

- 目标：依据社媒 PRD v2.0，实现“合法来源达人录入 → 平台身份与时效证据 → 多维筛选 → 品牌范围不可变受众快照”的最小闭环。
- 范围：后端领域模型、API、PostgreSQL 正向/回滚迁移、租户/品牌范围与角色门禁、幂等和追加审计、聚焦测试；不实现外部邀约发送、平台发布或第三方供应商抓取。
- 现状审计：现有 `channels` 负责企业聊天接入与回复投递，不是社媒发布域；TikTok 已有 PKCE、凭证外置、只读 Shop 授权和影子运行，但没有 SocialAccount/内容版本/排期/达人/邀约实体；通用 Approval/Operation 尚未声明社媒发布或邀约动作。
- 选择依据：发布与邀约写入仍受真实 Service ID、E3 写能力、限流/回执 PoC 和供应商合同约束，不能用 Mock 冒充闭环；达人证据与名单冻结不依赖外部副作用，可真实覆盖 SOC-FR-060～064 及 SOC-FR-070 的名单冻结基础，并为后续受控邀约提供稳定输入。
- 安全边界：不接收或保存邮箱、电话、私信地址等联系明文；仅记录联系依据类别。所有写入绑定当前可信租户，品牌范围通过现有业务资源授权复验；冻结名单不等于邀约批准，且不会触发任何外部调用。
- 已知衔接项：当前平台尚无独立 Brand 模型，本切片用已授权的 `BusinessResource`（`store`/`social_account`）作为 `brand_id` 范围锚点，待平台 Brand 合同落地后再做显式映射迁移。

## 2026-09-08 · P0 达人证据与受众冻结闭环（完成）

- 领域与接口：新增租户隔离的达人、公开平台身份、追加式证据、品牌范围受众快照和领域审计事件；提供达人创建/查询、证据追加、受众冻结/读取共 5 个 `/api/v1/social` 接口，并对所有写接口执行幂等键与请求摘要复验。
- 数据质量：证据显式记录来源引用、数据权利基础、联系依据、观察/过期时间；默认冻结仅使用最新且未过期证据，支持国家、语言、类目、粉丝量、互动率、受众国家、成本、质量和可联系依据的组合过滤；快照保存确定性成员清单与 SHA-256 摘要，明确 `outreach_authorized=false`。
- 权限与隐私：Casbin 与服务层双重限制为管理员、运营主管、TikTok BD/TAP 的最小职责集合；品牌资源必须属于当前租户、处于启用状态且具有角色范围授权。不定义邮箱、电话或私信地址字段，严格拒绝额外字段、联系地址型来源引用、含凭证的 URL 参数和不合规公开主页 URL。
- 数据库：新增 `20260908_social_creator_audiences_v1.sql` 及回滚脚本，使用 `timestamptz`、租户复合外键、品牌租户触发器、5 表 RLS/强制 RLS、最小权限授权，以及证据/快照/审计事件的数据库级追加保护。
- 验证证据：新增 6 个聚焦测试函数，覆盖跨租户与幂等、过期证据刷新、多维冻结、隐私/角色拒绝、API 鉴权/Casbin/审计、迁移契约；相关社媒+授权+TikTok 官方 OAuth+业务单元/资源套件为 `27 passed`。Ruff（新增文件全规则、既有修改文件 E9/F/I）与 `compileall` 通过。
- PostgreSQL 实证：在临时 PostgreSQL 17.11 空库执行正向/回滚迁移成功；正向结果为 5 表、5 触发器、10 条 RLS 策略，回滚后 0 个社媒表。运行态角色无法读取其他租户达人，跨租户品牌快照被触发器拒绝，证据更新被追加式触发器拒绝。
- 仓库全量回归：`2132 passed, 11 skipped, 22 failed`（22 分 33 秒）。失败均在本切片之外：广告执行环境开关、Windows 符号链接权限/进程时序、WeCom/Feishu 并发、harness/runner、运行锁、Markdown 与 MCP 探测；本次社媒及其授权/资源依赖回归无失败，未越权修改这些既有模块。
- 后续 P0/P1：真实平台 OAuth/账号生命周期、内容版本与发布排期、发布回执/限流/失败补偿、邀约审批与发送执行、供应商合同及抓取合规、独立 Brand 合同、联系渠道 `secret_ref` 与退订/抑制名单仍未实现；在相应 E3/Service ID/供应商与数据合同证据齐备前不得宣称端到端发布或邀约闭环。
